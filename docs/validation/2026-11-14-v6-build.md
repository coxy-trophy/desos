# DesOS v6 image validation

v6 adds DEs-UI 0.2.0 (the bird mark, lock-screen glass choices, Files as its own
window, the calculator, the installer-fit fix), Brave, Visual Studio Code, VLC,
CUPS, archive tools and the DEs-UI toolchain, desos-dev, desos-verify 2.2 and
desos-release 0.1.0~preview1+2 (LOGO=des-ui). Epiphany, Thunar, Ristretto and
Mousepad are gone.

## Artifact

- `output/live-v6/desos-0.1-preview-amd64.iso`, 2,960,074,752 bytes, SHA-256
  `5e4ada6e93bfe9859e98c75789cb1b5c26c9b05cfc9f5258d63c66a42a80577a`.
- Offline `desos-verify` at build: no failures; four checks unknown (no running
  system), as for v5.
- Written to the approved ProductCode USB stick on 2026-11-14 while the VM install
  test was still running, at the owner's request; full read-back matched
  (`output/live-v6/usb-write.json`).

## Found

- **GRUB cannot read the DesOS kernel as the installer wrote it.** GRUB 2.14 on
  the installed btrfs root reports "premature end of file /@/boot/vmlinuz-6.18.62-desos"
  and returns to the menu; the saved default (the DesOS kernel in Advanced
  options, set by select-upstream-kernel) then fails on every boot, desos-undo
  counts the failures and holds the menu, and only choosing the first entry (the
  higher-versioned Ubuntu 7.0 kernel) starts the system. The file is
  byte-identical to the signed package, not compressed, not sparse and one
  extent; a plain `cp` of it to a new file on the same filesystem boots. So the
  v4 "premature end of file" was not compression (v5's mount change did not fix
  it). Fixed for the next image: the installer's final step rewrites every
  kernel and initrd before select-upstream-kernel. The exact on-disk property
  GRUB trips over is not identified.
- The full integrity check in the live session failed once while the installer
  was running (6,780 kernel module files reported missing); run again
  afterwards it passed. Not reproduced or explained.
- The finish page's step rail overlaps its "when it says all done" note.
