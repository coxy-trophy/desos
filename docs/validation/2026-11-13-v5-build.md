# DesOS v5 image validation (0.1 Preview with the 0.2 components)

The v5 ISO adds the system, undo, verify, boot-theme and phonekey components,
the redesigned installer and the btrfs default to the 0.1 base. It booted live
in QEMU under BIOS and UEFI and on the owner's Acer Aspire A515-51G. The
install and installed-system boot have **not** been completed on v5.

## Artifact

- `output/live-v5/desos-0.1-preview-amd64.iso`, 2,199,244,800 bytes, SHA-256
  `4c63974ca2c3891b1081417f3d6d664adf4fddb97ca9f2b7cbf87911f6e0454f`.
- Before sealing, the image passed its own `desos-verify` offline check: 12 of
  16 checks passed, 0 failed, and 4 could only be checked on a running system.
- Written to the approved ProductCode USB stick on 2026-11-13. Every byte read
  back matched the SHA-256 (`output/live-v5/usb-write.json`). The owner asked
  to flash before the VM install tests, so the write used `usb_guard`'s
  identity, mount and read-back checks without its all-tests-passed gate; the
  receipt records which tests were observed.

## Observed

| Test | Result |
| --- | --- |
| BIOS live boot, QEMU | Desktop on 6.18.62-desos. `desos-verify` quick check: 16 of 16 passed. zram swap and firewall active. |
| UEFI live boot, QEMU | Install entry opened the installer. |
| Installer, QEMU | Step rail, slideshow and welcome art rendered. The checked radio indicator is a clean dot inside its ring. The auto-login checkbox is hidden and skipped by Tab. Erase disk is not preselected, and btrfs is the default. |
| Owner's laptop, live, UEFI | Themed GRUB menu, desktop, Wi-Fi, sound, HDMI, keyboard and touchpad, battery level, webcam, suspend on lid close: all reported working by the owner. |

## Found and fixed on the way (v4 image)

- `desos-verify` could not read the running kernel release on any real boot:
  Linux refuses `/proc/sys` reads of 4 MiB or more. Fixed in `desos-verify` 2.1.
- The installed system never started. GRUB 2.14 could not read the
  zstd-compressed kernel on the btrfs root ("premature end of file").
  The installer now mounts btrfs without compression. **v5 has this fix, but
  it has not been booted from an installed disk yet.**
- The build worker's own unattended-upgrades restarted the build mid-ISO; it is
  now disabled in the worker.

## Still open

- The v5 install and installed boot have not been run, either in a VM or on
  hardware. That leaves the btrfs/GRUB fix, self-healing boot, AppArmor
  enforcing and live-account cleanup unobserved.
- The laptop's legacy BIOS mode does not list the stick, which has a GPT
  protective MBR; it boots in UEFI mode.
- In BIOS mode GRUB uses 640x480 and the theme overflows.
- The installer window is wider than the DEs-UI workspace on the partitions
  and summary pages; this needs a compositor fix.
- Calamares sets Akan number and date formats for Accra; it can be changed on
  the location page.
